# Лабораторная работа №2
## Тема
Параметры генерации и конфигурация больших языковых моделей

## Цель работы
Изучить, как параметры влияют на поведение модели, научиться управлять поведением LLM 
с помощью параметров генерации и системных инструкций,
а также экспериментально выбирать конфигурацию модели под конкретную прикладную задачу.

## Задачи
1. Изучить теорию, представленную в лабораторной работе
2. Выбрать модель LLM для эксперимента
3. Подготовить тестовый набор данных для произведения промптов.
4. Разработать код, позволяющий изменять параметры модели по отдельности. 
5. Проанализировать три одинаковых запроса, меняя системный промпт, по критериям корректности, следованиям инструкции и формату.
6. Проанализировать 5 повторов одного и того же запроса, изменяя температуру (0, 0.3, 0.7); 
7. Проанализировать ответы модели, изменяя лимит ответа;

**1.1 Изучение теории**  
&emsp;&emsp; Для работы над лабораторной работой 
необходимо было изучить следующие понятия:  
&emsp;&emsp;System_prompt - из 1 лабораторной работы нам уже известно, что он 
задаёт роль, правила, ограничения и ожидаемый стиль поведения модели. 
В прикладной системе именно здесь обычно размещают постоянные требования, 
не зависящие от конкретного пользовательского вопроса.  
&emsp;&emsp;Temperature управляет распределением вероятностей 
при выборе следующего токена - небольшие значения параметра обычно делают 
ответы более стабильными и предсказуемыми, а большие — более вариативными и хаотичными. 
Точная шкала и допустимый диапазон зависят от API.
&emsp;&emsp;Max_tokens - позволяет ограничивать длину ответа. Слишком маленькое значение приводит к обрыву ответа, 
слишком большое — допускает ненужную многословность, большее количество дополнительной информации
и увеличивает расход ресурсов.  
&emsp;&emsp; Также для понимания работы иных параметров было интересно рассмотреть такие понятия, как: 
seed для повышения воспроизводимости, frequency/presence penalties для управления повторяемостью, stop-последовательности, 
top_p для ограничения множества рассматриваемых токенов суммарной вероятностью p.  
&emsp;&emsp; Важно также знать о существовании reasoning моделей и их особенностях, которые могут 
иметь собственный механизм управления вычислительным усилием 
и не поддерживать привычные параметры sampling либо ограничивать их использование.

**Этап 2** Разработка кода  
&emsp;&emsp; Рассмотрим наиболее важные и интересные для нас части кода.
В отличие от прошлой лабораторной работы, здесь нам необходимо иметь возможность

Полный код необходимой для этого функции
```python
def ask_model(prompt: str,
    *,
    experiment: str = "default",
    system: str | None = None,
    system_id: str | None = None,
    temperature=None,
    max_tokens=None,
    repeat: int = 1,
):
    results = load_results()
    ok, failed = 0, 0
    latencies = []

    for r in range(1, repeat + 1):
        print(f"[{r}/{repeat}] {prompt}")

        messages = []
        if system:
            messages.append({"role": "system", "content": system})
        messages.append({"role": "user", "content": prompt})

        kwargs = {"model": MODEL_NAME, "messages": messages}
        if temperature is not None:
            kwargs["temperature"] = temperature
        if max_tokens is not None:
            kwargs["max_tokens"] = max_tokens

        started = time.perf_counter()
        usage_dict = None
        try:
            response = client.chat.completions.create(**kwargs)
            answer = response.choices[0].message.content
            error = None

            usage = getattr(response, "usage", None)
            if usage is not None:
                usage_dict = {
                    "prompt_tokens": getattr(usage, "prompt_tokens", None),
                    "completion_tokens": getattr(usage, "completion_tokens", None),
                    "total_tokens": getattr(usage, "total_tokens", None),
                }
        except Exception as e:
            answer = None
            error = f"{type(e).__name__}: {e}"
        latency = time.perf_counter() - started

        if error is None:
            ok += 1
            latencies.append(latency)
            tokens_info = (
                f", tokens: {usage_dict['total_tokens']}"
                if usage_dict and usage_dict.get("total_tokens") is not None
                else ""
            )
            print(f"    OK, {latency:.2f} c{tokens_info}")
        else:
            failed += 1
            print(f"    Ошибка: {error}")

        results.append({
            "model": MODEL_NAME,
            "experiment": experiment,
            "temperature": temperature,
            "max_tokens": max_tokens,
            "system_id": system_id,
            "system_prompt": system,
            "repeat": r,
            "latency_s": round(latency, 3),
            "answer": answer,
            "usage": usage_dict,
            "error": error,
        })

    print(f"\nВсего запросов: {repeat}, успешных: {ok}, с ошибками: {failed}")
    if latencies:
        avg_latency = sum(latencies) / len(latencies)
        print(f"Среднее время ответа: {avg_latency:.2f} c")

    save_to_json(results)
```
